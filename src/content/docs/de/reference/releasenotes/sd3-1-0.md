## Was ist neu in swiftDialog 3.1.0?

### Ablauf (Dialoge mit mehreren Schritten)

swiftDialog 3.1.0 führt **Workflow** ein – eine leistungsstarke neue Funktion zum Erstellen von mehrstufigen Dialogen, die über eine einzige JSON-Konfigurationsdatei gesteuert werden.

- Definieren Sie ein Array von Workflow-Seiten mithilfe des Schlüssels `workflow` in Ihrer JSON-Datei, wobei jede Seite ihren eigenen Titel, ihre eigene Meldung, ihr eigenes Symbol und ihre eigenen Eingabefelder hat
- Benutzer können zwischen den einzelnen Elementen (Karten) vorwärts und rückwärts navigieren, wobei die eingegebenen Daten während der Navigation erhalten bleiben
- Die zusammengefassten Eingabedaten von allen Karten werden nach Abschluss des Vorgangs als einzelne JSON-Ausgabe zurückgegeben
- Globale Konfigurationseinstellungen (die außerhalb des `cards`-Arrays definiert sind) dienen als Standardwerte, die jedoch für jede einzelne Karte überschrieben werden können
- Eine neue `--onadvance` Funktion ermöglicht es, ein Shell-Skript auszuführen, wenn ein Benutzer zwischen verschiedenen Ansichten wechselt. Das Skript erhält den aktuellen Index der Ansicht, die ID der Ansicht und die Benutzereingabe über die Standardeingabe (stdin) im JSON-Format. Das Skript kann den Wechsel zur nächsten Ansicht verhindern, indem es mit einem Nicht-Null-Wert beendet wird
- Die Pflichtfelder werden für jede einzelne Karte überprüft, bevor fortgefahren werden kann
- Die Symbolleiste passt sich automatisch an (Zurück / Weiter / Fertigstellen) und zeigt die entsprechenden Schaltflächen basierend auf der aktuellen Position im Ablauf

Workflow-Seiten können auch basierend auf Benutzereingaben (Auswahl aus Dropdown-Menüs oder Zustand von Kontrollkästchen) verzweigt werden, ohne dass ein Callback-Skript erforderlich ist, und der Text der "Weiter/Zurück"-Buttons ist über `--nextbuttontext` / `--previousbuttontext` anpassbar.

Sehen Sie die [Workflow](/de/advanced/workflows)]-Dokumentation für vollständige Informationen.

### Benachrichtigungen

> ⚠️ **Hinweis:** Ab macOS 26.4 funktioniert das Ändern des Anwendungssymbols von Dialog.app möglicherweise nicht wie erwartet, wenn dies dazu dient, das Benachrichtigungssymbol festzulegen. "Pseudo-Benachrichtigungen" können in bestimmten Fällen helfen, dieses Problem zu beheben

#### Benachrichtigungs- und Banner-App-Pakete

Benachrichtigungen werden jetzt von speziellen Hilfsprogrammen (`Dialog Alert.app` und `Dialog Banner.app`) und nicht mehr von der Anwendung Dialog.app selbst ausgeliefert.

- Separate Apps für Benachrichtigungen im Stil von "Alerts" und "Bannern", um sicherzustellen, dass die Benachrichtigungen auf macOS korrekt dargestellt werden
- Hilfsanwendungen sind in `Dialog.app/Contents/Helpers/` integriert und werden automatisch vom `dialog`-Befehlszeilen-Launcher aufgerufen, wenn `--style alert` oder `--style banner` zusammen mit `--notification` verwendet werden
- Der Hinweis "Benachrichtigungen zulassen" bleibt nun aktiv, bis er manuell geschlossen wird – er wird nicht mehr automatisch geschlossen
- Neue App-Symbole für die Helfer-Apps zur Benachrichtigung

> **Hinweis zur Veraltung:** Das Senden von Benachrichtigungen über `Dialog.app` direkt (ohne `--style alert` oder `--style banner`) wird nicht mehr unterstützt. Eine Warnung wird jetzt in `stderr` ausgegeben, wenn diese veraltete Methode verwendet wird. Dieses Verhalten wird in einer zukünftigen Version entfernt, und Benachrichtigungen ohne angegebenen Stil werden standardmäßig als Banner mithilfe des `Dialog Banner.app`-Tools angezeigt.

#### Simulierte Benachrichtigungen

"Pseudo-Benachrichtigungen" sind benutzerdefinierte Fenster im Stil von Benachrichtigungen, die von swiftDialog selbst erstellt werden, im Gegensatz zu den Systembenachrichtigungen von macOS. Sie erscheinen am rechten Rand des Bildschirms und ahmen das Aussehen der nativen Benachrichtigungen nach, wobei sie einen leicht transparenten Hintergrund verwenden.

> Falsche Benachrichtigungen sind keine Systembenachrichtigungen. Sie bleiben nicht erhalten, nachdem sie geschlossen wurden, und folgen nicht den Standardregeln für macOS-Systembenachrichtigungen.

[Mehr Informationen](https://beta.swiftdialog.app/advanced/notifications/#pseudo-notifications)

### Inspektionsmodus
Eine umfangreiche Aktualisierung des Inspektionsmodus (der in Version 3.0.x eingeführt wurde):

- **Compliance-Übersichten** – Benutzeroberfläche, die von plist-Dateien gesteuert wird, mit einem `ComplianceAggregatorService`, gemeinsamen `compliance-summary` / `findings-list` Inhaltsblöcken und automatisch konfigurierten Bento-Elementen.
- **Gesteuerte Ablaufsteuerung** — Nachrichten werden nur weitergeleitet, wenn ein überwachtes Attribut erfüllt ist, optional mit interprozesskommunikation und Zeitüberschreitungen pro Eintrag (`stepType: "cadence"`); sowie eine **Karussell-Anzeige** (ähnlich DEPNotify mit Symbolzeile für "erledigt", "aktiv" und "ausstehend").
- **`managedpref` Attribut:** — Die Steuerung/das Gating kann entweder auf Geräteebene oder auf Benutzerebene angewendet werden `/Library/Managed Preferences/<domain>.plist`.
- **`ManagedValueRef`** — Die individuelle Gestaltung pro Nutzer zieht Farben und Markenzeichen aus verschiedenen Bereichen des MDM-Konfigurationsdatensatzes.
- **Erzwungene Darstellung** — `appearance` Der Konfigurationsschlüssel erzwingt das helle oder dunkle Farbschema des Inspektionsfensters, unabhängig von den Systemeinstellungen (#669).
- **Neugestaltung von Voreinstellung 3:** (Hero-Bereich, Fußzeile, schlanke Marken-Fortschrittsanzeige); **permanentes Markenlogo in der Fußzeile** mit Variante für den Dunkelmodus; **individuelle Beschreibungen für jedes Element** in den Voreinstellungen 1/2/3/5/6 (#663); einheitliches, markenbezogenes Informationsfeld.
- **IPC / Sitzungen** — Entdeckung von Sitzungen pro Prozess-ID (`--published-sessions-dir` veröffentlicht `<pid>.json`); Sitzungsdaten im JSON-Format, angereichert mit Pfaden zu `resultFile`, `readinessFile` und `eventFile`.
- **Optimierungsdurchlauf (PR #684):** Einzelner Ladeindikator im Header + statische Statuspunkte für gleichzeitige Installationen; Vollbild-Hero-Bilder (nicht beschnitten); klare Übergänge für Preset 5; verbesserte Einführung für Preset 5 (betonte Textpassagen, zentrierte Browser-Dropdowns); einheitliches 12-Punkt-Layout für Presets 1–3 und den Hintergrundbild-Auswahlbereich; Bereitstellungsanzeige für Presets 1/2/3; Live-Protokollierung von Interaktionen für Dropdowns, Radiobuttons und Kontrollkästchen; Anzeige des Berichts für Preset 4 über `progressMode "report"` und Fortschrittsanzeige über den `progress:` IPC-Befehl; einheitliche Konfigurationseingabe mit strenger Schemavalidierung (toleriert Zahlen und Boolesche Werte in Anführungszeichen von MDM-Tools) mit detaillierten JSON-Fehlermeldungen.

### Banner-Verbesserungen

Das `--bannerimage`-Argument unterstützt nun neben Bilddateien auch Optionen für Vollfarben und Farbverläufe.

**Banner in einfarbiger Ausführung:**

```sh
dialog --bannerimage "colour=accent"
dialog --bannerimage "colour=#0066CC"
dialog --bannerimage "colour=blue,nogradient"   # disable the default gradient overlay
```

Standardmäßig wird eine subtile Farbverlaufsoberlagerung angewendet. Fügen Sie `,nogradient` hinzu, um diese zu deaktivieren.

**Banner mit Farbverlauf:**

```sh
dialog --bannerimage "gradient=red,orange,yellow"
dialog --bannerimage "gradient=red,orange,yellow:angle=135"
```

Farben werden durch kommagetrennte Namen oder Hex-Werte angegeben. Das optionale `:angle=<degrees>`-Suffix bestimmt die Richtung des Farbverlaufs (0 = von unten nach oben, 90 = von links nach rechts, 180 = von oben nach unten; Standardwert ist 90).

Die gleichen Schlüsselwörter `colour=` und `gradient=` funktionieren ebenfalls für `--background` (Wasserzeichen)-Bilder.

### Titelverbesserungen

**Argument für Untertitel (zur Verwendung mit `--title` und `--bannertitle`)**

`--subtitle` ermöglicht es Ihnen, einen Untertitel unterhalb des Haupttitels hinzuzufügen. Dies ist nützlich, um dem Benutzer zusätzliche Informationen oder Anweisungen zu geben.

```sh
dialog --title "Main Title" --subtitle "This is a subtitle"
```

Der Text des Untertitels wird mit den gleichen Schriftattributen wie der Titel formatiert, jedoch mit einer Deckkraft von 75 %. Wenn ein Hintergrundbild verwendet wird, übernimmt der Untertitel auch die Formatierung des Hintergrundtextes (weiße Farbe, Schatten). `--bannertext enable`

**Versatz der Schrift für den Titel**

`--titlefont` akzeptiert jetzt einen `offset=<float>`-Parameter, um den Titeltext innerhalb seines Containers vertikal zu verschieben. Dies ist nützlich, wenn Bannerbilder mit überlagertem Titeltext verwendet werden, kann aber auch in normalen Dialogfenstern eingesetzt werden, um die Positionierung des Titels feinabzustimmen.

```sh
dialog --titlefont "size=36,offset=-10"
```
### Baukasten / Konstruktionsspielzeug
Wesentliche Verbesserungen im `--builder`-Modus:
- **Exportieren** Sie das aktuelle Design in das **JSON-Format** und als **Befehlszeilenaufruf**.
- **Markdown-Quellen** – Definieren Sie die Nachricht / Infobox aus einer **`.md` Datei oder URL**; der Generator lädt den Inhalt für die Vorschau, während die Exporte auf die Datei/URL verweisen.
- Eine Option zur Auswahl eines Hintergrundbildes für den Bildschirm ist im Fensterbereich aufgetaucht.
- **Drag-and-Drop-Funktion zum Neuanordnen** für Textfelder, Kontrollkästchen und Listenelemente (jetzt als Liste mit Drag-Handles dargestellt, ähnlich wie das Bilderfenster).
- **Strukturierter Editor für Button-Symbole** – Name, Position, Rendering-Modus, Größe und Farbe/Palette des Symbols werden als separate Steuerelemente angezeigt, wobei eine **fixe, interaktive Vorschau** der Button-Symbole dargestellt wird.
- Ein gemeinsames Symbol-Auswahlfeld für SF-Symbole in den Bereichen für Symbole, Listen und Kontrollkästchen; der Titelbalken wird jetzt in den Export einbezogen; das Dock-Symbol wird angezeigt, während sich der Builder im Bearbeitungsmodus befindet.

### Weitere neue Optionen
- **Hintergrundbildschirm** – Zeigt ein Bild hinter Dialogfenstern an (Feature-ID: `--screenbackground`, #655).
- **Breite des Infoboxes:** – Passen Sie die Textfläche des Infoboxes unabhängig vom Symbol an (#665).
- **aria2-Unterstützung für Teil-Dateien** — `cacheExtensions` ist ein konfigurierbares Array, das Elemente als "herunterladen" markiert (Standardeinstellungen `download`, `pkg`, `dmg`; `aria2` für aria2 hinzufügen) (#617).

### Früher nicht dokumentierte Argumente

Die folgenden Argumente waren in früheren Versionen verfügbar, wurden aber nicht dokumentiert. Hilfetexte sind jetzt für jeden dieser Punkte über `--help <argument>` verfügbar.

| Argument | Beschreibung |
|---|---|
| `--helpalignment [left\|centre\|right]` | Legt die Textausrichtung der Nachricht im Hilfeblatt fest |
| `--helpsheetbuttontext <text>` | Legt die Beschriftung des Schließen-Buttons im Hilfeblatt fest (Standard: `OK`). |
| `--iconalttext <text>` | Beschriftung für das Dialog-Symbol zur Verbesserung der Barrierefreiheit |
| `--bannerheight <num>` | Legt die Höhe des Bereichs für das Bannerbild in Punkten fest |
| `--selectstyle [list\|radio\|searchable\|multiselect]` | Globale Anzeigestil-Einstellungen für alle Auswahllisten |
| `--progresstextalignment [left\|right]` | Horizontale Ausrichtung des Textes in der Fortschrittsanzeige (Standard: zentriert). |
| `--verbose` | Aktivieren Sie eine ausführliche Protokollausgabe, die an die Standardfehlerausgabe (stderr) gesendet wird |
| `--eula` | Anzeige der Meldung im EULA-Modus (mit Monospace-Schrift, scrollbar). |
| `--alwaysreturninput` | Geben Sie die Benutzereingabe für alle Rückgabecodes zurück, nicht nur für den Rückgabecode 0 |
| `--hidetimer` | Verbergen Sie den Countdown-Anzeiger während der automatischen Übergänge in der Bilderserie |
| `--listfonts` | Geben Sie alle verfügbaren Schriftnamen auf der Standardausgabe aus |

### Fehlerbehebungen

- **Behebung von Fehler #632** – Das mehrfache Auswahlelement zeigt jetzt ausgewählte Tags korrekt in einem scrollbaren Layout an
- Das Laden von Dateien oder URLs führt nicht mehr zu Fehlern, wenn die angegebenen Dateipfade nicht existieren (#654).
- **Mini-Ansicht** zeigt jetzt formatierten Text anstelle von Inline-Text (#677); die Größe wurde für **macOS 26 (Tahoe)** und neuere Versionen angepasst (#649).
- Überprüfen Sie **Voreinstellung 2**: automatische Verfolgung der aktuellen Installation (#565); Berücksichtigung benutzerdefinierter Statusmeldungen und Fortschrittsanzeigen (#571); Untertitel im Header werden aus `message` übernommen (#670).
- Überprüfen: **`appearance: dark`** wird jetzt berücksichtigt, wenn es in der JSON-Datei im Überprüfungsmodus festgelegt ist.

### Änderungen und Funktionen, die nicht mehr unterstützt werden
- Das Senden von Benachrichtigungen über **`Dialog.app` direkt (ohne `--style`) wird nicht mehr empfohlen** – verwenden Sie stattdessen `--style alert` / `--style banner`; ältere Systeme geben eine Warnung auf der Standardfehlerausgabe aus.
- Die Befehle "stub" `--inspect-schema` und "stub" `--schema-validate` wurden entfernt.
