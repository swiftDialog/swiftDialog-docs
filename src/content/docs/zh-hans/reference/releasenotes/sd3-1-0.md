## swiftDialog 3.1.0 的新功能：

### 工作流程（多步骤对话）

swiftDialog 3.1.0 引入了 **工作流程 (Workflow)**，这是一个强大的新功能，可以让你通过单个 JSON 配置文件构建多步骤的对话界面。

- 使用 JSON 中的 `workflow` 键，定义一个工作流页面的数组，每个页面都有自己的标题、消息、图标和输入字段。
- 用户可以在卡片之间**向前和向后**浏览，并且在浏览过程中，输入内容会得到保留。
- 所有卡片输入的数据在完成时会被汇总，并以单个 JSON 格式的输出返回。
- 全局配置属性（定义在`cards`数组之外）作为默认设置，但每个卡片可以进行覆盖。
- 新的`--onadvance`参数允许在用户在卡片之间切换时，执行一个shell脚本。该脚本会接收当前卡片索引、卡片ID以及用户输入（通过标准输入以JSON格式），并且可以通过以非零状态退出来阻止用户的继续操作。
- 在继续操作之前，会对每个卡片中的必填字段进行验证。
- 按钮栏会根据卡片的位置自动调整显示内容，包括“返回”、“下一步”和“完成”按钮。

工作流程页面还可以根据用户输入（下拉菜单选择或复选框状态）进行分支处理，无需任何回调脚本，并且“下一步/上一步”按钮的文字可以通过`--nextbuttontext`/`--previousbuttontext`进行自定义。

请参考[工作流程](/zh-hans/advanced/workflows))以获取完整文档。

### 通知

> ⚠️ **注意：** 从 macOS 26.4 版本开始，设置 Dialog.app 应用程序的图标以更改通知图标可能无法按预期工作。 虚拟通知可能有助于解决某些类型的通知问题。

#### 提示和横幅应用组合包

现在，通知是通过专门的辅助应用程序（`Dialog Alert.app` 和 `Dialog Banner.app`）来发送的，而不是直接通过 Dialog.app 本身。

- 为“提醒”和“横幅”两种类型的通知，分别提供独立的应用程序，以确保macOS通知以正确的显示方式呈现。
- 辅助应用程序被包含在`Dialog.app/Contents/Helpers/`中，当使用`--style alert`或`--style banner`与`--notification`一起使用时，`dialog`命令行启动器会自动调用这些辅助应用程序。
- “批准通知”的提示框现在会一直显示，直到用户手动关闭，不再会自动消失。
- 为通知助手应用更新了新的图标。

> **弃用通知：** 直接通过 `Dialog.app` 发送通知（不使用 `--style alert` 或 `--style banner`）已被弃用。当检测到这种旧用法时，现在会在 `stderr` 中显示警告。 在未来的版本中，此行为将被移除，并且没有指定样式的通知将默认以横幅形式显示，并使用 `Dialog Banner.app` 辅助工具。

#### 虚假通知

“伪通知”是 swiftDialog 本身渲染的、具有通知窗口风格的界面元素，而不是 macOS 系统通知。它们从屏幕右边缘滑入，并模仿原生通知的外观，采用半透明的背景材质。

> “伪通知”不是系统通知。一旦被关闭，它们不会保留，并且不遵循macOS系统通知的常规规则。

[更多信息](https://beta.swiftdialog.app/advanced/notifications/#pseudo-notifications)

### 检查模式
对检查模式进行了一次重要的更新（该功能在3.0.x版本中首次发布）。

- **Compliance dashboards** — plist-driven UI with a `ComplianceAggregatorService`, shared `compliance-summary` / `findings-list` content blocks, and auto-bound bento cells.
- **带锁的流程控制引擎** — 消息仅在监视的属性满足时才会继续推进，并可以选择启用进程间通信（IPC）功能，以及为每个条目设置超时时间（`stepType: "cadence"`）；此外，还提供一个**轮播式流程状态指示器**（类似于DEPNotify的完成/活动/待处理图标行）。
- **`managedpref` 属性** — 节拍/门控功能可以读取`/Library/Managed Preferences/<domain>.plist`（设备或用户范围）。
- **`ManagedValueRef`** — 每个租户的品牌定制功能，可以从不同的移动设备管理（MDM）配置信息域中提取品牌颜色和宣传语。
- **强制外观** — `appearance` `config` 键可以强制使检查窗口呈现明亮或黑暗模式，而与操作系统设置无关（#669）。
- **预设方案3的重新设计**（包含主内容区域、页脚、以及精简的品牌进度条）；**持久显示的品牌Logo**，并提供深色模式版本；**每个项目的详细描述**（适用于预设方案1/2/3/5/6，#663）；统一采用品牌色调的信息提示标签。
- **IPC / 会话** - 基于进程ID (PID) 的会话发现 (`--published-sessions-dir` 发布 `<pid>.json`)；会话的 JSON 数据包含 `resultFile`、`readinessFile` 和 `eventFile` 的路径信息。
- **优化版本 (PR #684)：** 单个头部加载指示器 + 用于并发安装的静态状态指示点；完整（未裁剪）的基于文件的英雄图片；Preset 5 的清晰过渡效果；优化了 Preset 5 的引导流程（强调了文字，并将浏览器下拉菜单居中）；在 Preset 1–3 和壁纸选择器中统一使用 12pt 的间距网格；为 Preset 1/2/3 添加了就绪信号；为下拉菜单/单选按钮/复选框添加了实时交互日志事件；可以通过 `progressMode "report"` 查看 Preset 4 的报告，并通过 `progress:` IPC 命令查看外部进度；统一了配置导入流程，并使用了严格的模式验证（对来自 MDM 工具的带引号的数字/布尔值具有容错性），同时提供了详细的 JSON 错误报告。

### 横幅增强功能

现在，该参数除了支持图像文件外，还支持纯色和渐变色选项。`--bannerimage`

纯色横幅。

```sh
dialog --bannerimage "colour=accent"
dialog --bannerimage "colour=#0066CC"
dialog --bannerimage "colour=blue,nogradient"   # disable the default gradient overlay
```

默认情况下，会应用一种微妙的渐变效果。要禁用此效果，请在代码末尾添加 `,nogradient`。

多色渐变横幅。

```sh
dialog --bannerimage "gradient=red,orange,yellow"
dialog --bannerimage "gradient=red,orange,yellow:angle=135"
```

颜色以逗号分隔的名称或十六进制值表示。 可选的`:angle=<degrees>`后缀设置渐变方向（0 = 自下而上，90 = 自左向右，180 = 自上而下；默认值为 90）。

相同的`colour=`和`gradient=`关键词也适用于`--background`（水印）图像。

### 标题优化

字幕说明（适用于`--title`和`--bannertitle`）。

`--subtitle` 允许您在主标题下方添加字幕。这对于向用户提供额外的背景信息或操作说明非常有用。

```sh
dialog --title "Main Title" --subtitle "This is a subtitle"
```

字幕文本的字体样式与标题相同，但透明度为75%。当使用横幅图片时，字幕也会采用横幅文本的样式（白色，带阴影）。`--bannertext enable`

标题字体偏移量。

`--titlefont` 现在接受一个 `offset=<float>` 参数，用于在容器内垂直调整标题文本的位置。 当使用带有叠加标题文本的横幅图片时，此参数非常有用，但也可用在常规对话框中，以微调标题的位置。

```sh
dialog --titlefont "size=36,offset=-10"
```
### 拼装玩具 / 建筑模型套件
对“高级”模式进行了重大改进：`--builder`
- 将当前设计导出为 **JSON** 格式，并生成用于命令行调用的命令。
- **Markdown 来源** — 可以从 **`.md` 文件或 URL** 中设置消息/信息框；构建工具在实时预览时加载内容，而导出时则引用该文件/URL。
- “屏幕背景”图像选项出现在窗口区域。
- 支持通过拖拽来重新排序文本字段、复选框和列表项（现在采用基于列表的拖拽方式，并带有拖拽手柄，与图片面板的样式一致）。
- **结构化按钮符号编辑器** — 提供独立的控件，用于设置SF Symbol的名称、位置、渲染模式、大小以及颜色/调色板，并提供**实时预览**，方便用户查看按钮符号的效果。
- 图标选择器现在可以在图标、列表和复选框区域共享使用；导出的文件现在包含横幅标题；在构建模式下，会显示 Dock 图标。

### 其他新的选择
- **屏幕背景** — 通过 `--screenbackground` (#655) 在对话窗口的后面显示一张图片。
- **信息框宽度** — 独立设置信息框的文本区域大小，与图标分离 (#665)。
- **aria2 partial-file support** — `cacheExtensions` is a configurable array marking items as "downloading" (defaults `download`, `pkg`, `dmg`; add `aria2` for aria2) (#617).

### 问题修复

- **修复 #632** —— 多选下拉菜单现在可以正确地显示已选中的标签，并以可滚动的列表形式呈现。
- 文件/URL 加载功能不再在 **不存在的文件路径** 下报错 (#654)。
- **迷你视图** 现在显示结构化文本，而不是行内文本（#677）；尺寸已针对 macOS 26 (Tahoe) 及更高版本进行调整（#649）。
- 检查 **预设模式 2**：自动跟踪正在进行的安装过程 (#565)；尊重自定义的状态和进度文本 (#571)；标题副标题来源于 `message` (#670)。
- 检查：**`appearance: dark`** 现在在以检查模式设置的 JSON 文件中会被识别和处理。

### 变更与废弃功能
- 通过 **`Dialog.app` 直接发送通知（不使用 `--style`）已被弃用**，请使用 `--style alert` / `--style banner`；旧用法会在标准错误输出中发出警告。
- 移除了 `**`--inspect-schema`**` 和 `**`--schema-validate`**` 命令。
