## Quoi de neuf dans swiftDialog 3.1.0 ?

### Flux de travail (dialogues en plusieurs étapes).

swiftDialog 3.1.0 introduit **Workflow**, une nouvelle fonctionnalité puissante permettant de créer des dialogues multi-étapes à partir d'une seule configuration JSON.

- Définissez un tableau de pages de flux de travail en utilisant la clé `workflow` dans votre fichier JSON, chaque page ayant son propre titre, message, icône et champs de saisie
- Les utilisateurs peuvent naviguer **vers l'avant et vers l'arrière** entre les différentes sections, et les informations saisies sont conservées pendant la navigation
- Les données collectées à partir de toutes les cartes sont renvoyées sous forme d'un seul fichier JSON une fois le processus terminé
- Les propriétés de configuration globales (définies en dehors du tableau `cards`) servent de valeurs par défaut, qui peuvent être modifiées individuellement pour chaque carte
- La nouvelle `--onadvance` option permet à un script shell de s'exécuter lorsque l'utilisateur passe d'une carte à l'autre. Le script reçoit l'index de la carte actuelle, l'identifiant de la carte et les entrées de l'utilisateur via l'entrée standard (stdin) au format JSON, et peut empêcher l'utilisateur de passer à la carte suivante en se terminant avec un code différent de zéro
- La validation des champs obligatoires est appliquée pour chaque carte avant de passer à l'étape suivante
- La barre de boutons s'adapte automatiquement (Retour / Suivant / Terminer) en fonction de la position de la carte

Les pages de flux de travail peuvent également créer des **branches** en fonction des entrées de l'utilisateur (sélection dans une liste déroulante ou état d'une case à cocher), sans nécessiter de script de rappel, et le texte des boutons "Suivant/Précédent" est personnalisable via `--nextbuttontext` / `--previousbuttontext`.

Consultez [Workflow](/fr/advanced/workflows)] pour obtenir la documentation complète.

### Notifications

> ⚠️ **Note :** À partir de macOS 26.4, la modification de l'icône du paquet Dialog.app afin de définir l'icône de notification peut ne pas fonctionner comme prévu. Les notifications simulées peuvent aider à résoudre ce problème pour certains types de notifications

#### Lots de fonctionnalités, un prix abordable

Les notifications sont désormais transmises par des applications auxiliaires spécifiques (`Dialog Alert.app` et `Dialog Banner.app`), plutôt que par l'application Dialog.app elle-même.

- Des applications distinctes pour les notifications de type « alerte » et « bannière », garantissant ainsi la présentation correcte des notifications sur macOS
- Les applications utilitaires sont intégrées à `Dialog.app/Contents/Helpers/` et sont automatiquement appelées par le lanceur en ligne de commande `dialog` lorsque `--style alert` ou `--style banner` est utilisé en conjonction avec `--notification`
- L'alerte "Approuver les notifications" reste désormais affichée jusqu'à ce qu'elle soit annulée ; elle ne disparaît plus automatiquement
- Nouvelles icônes pour les applications d'assistance de notification

> **Avertissement de dépréciation :** L'envoi de notifications via `Dialog.app` directement (sans `--style alert` ni `--style banner`) est obsolète. Un message d'avertissement est maintenant affiché dans `stderr` lorsque cette méthode obsolète est détectée. Ce comportement sera supprimé dans une version future, et les notifications sans style spécifié seront affichées par défaut sous forme de bannières en utilisant l'outil d'assistance `Dialog Banner.app`.

#### Notifications simulées

Les notifications personnalisées sont des fenêtres de type notification créées par swiftDialog lui-même, et non par le système macOS. Elles apparaissent en glissant depuis le bord droit de l'écran et reproduisent l'apparence des notifications natives, avec un fond semi-transparent.

> Les notifications simulées ne sont pas des notifications système. Elles disparaissent une fois qu'elles ont été masquées et ne suivent pas les règles standard des notifications système de macOS.

[Plus d'informations](https://beta.swiftdialog.app/advanced/notifications/#pseudo-notifications)

### Mode d'inspection
Une mise à jour importante du mode d'inspection (qui a été introduite dans la version 3.0.x) :

- **Tableaux de bord de conformité** — Interface utilisateur basée sur des fichiers plist, avec une structure `ComplianceAggregatorService`, des blocs de contenu `compliance-summary` / `findings-list` partagés, et des cellules "bento" automatiquement configurées.
- **Moteur de cadence avec contrôle d'accès** — les messages progressent uniquement lorsque qu'un attribut surveillé est satisfait, avec une option de communication interprocessus et des délais d'attente configurables pour chaque entrée (`stepType: "cadence"`) ; ainsi qu'une **représentation circulaire** (une rangée d'icônes de type DEPNotify indiquant l'état : terminé, actif, en attente).
- **`managedpref` Attribut** — La cadence/le contrôle peut être appliqué à l'échelle de l'appareil ou de l'utilisateur `/Library/Managed Preferences/<domain>.plist`.
- **`ManagedValueRef`** — La personnalisation par utilisateur permet d'appliquer les couleurs et les messages de la marque en fonction de différents domaines de configuration MDM.
- **Apparence forcée** — `appearance` La clé de configuration "forced appearance" force l'affichage clair ou sombre de la fenêtre d'inspection, indépendamment des paramètres du système d'exploitation (#669).
- **Refonte du modèle 3** (bloc principal, pied de page, barre de progression de la marque simplifiée) ; **logo de la marque fixe dans le pied de page**, avec une version pour le mode sombre ; **descriptions spécifiques à chaque élément** dans les modèles 1, 2, 3, 5 et 6 (n° 663) ; badge d'information unifié avec la couleur de la marque.
- IPC / sessions : Découverte des sessions par PID (`--published-sessions-dir` publie `<pid>.json`) ; le fichier JSON de la session est enrichi avec les chemins `resultFile`, `readinessFile` et `eventFile`.
- **Améliorations (PR #684) :** indicateur de chargement unique en haut de page + points de statut statiques pour les installations simultanées ; images d'illustration complètes (non rognées) basées sur des fichiers ; transitions précises pour le préréglage 5 ; amélioration de l'intégration du préréglage 5 (texte mis en évidence, menus déroulants du navigateur centrés) ; grille d'espacement unifiée de 12 points pour les préréglages 1 à 3 et le sélecteur de fonds d'écran ; ajout d'indicateurs de disponibilité pour les préréglages 1/2/3 ; enregistrement des événements d'interaction en temps réel pour les menus déroulants, les boutons radio et les cases à cocher ; affichage des rapports du préréglage 4 via `progressMode "report"` et suivi de la progression externe via la commande IPC `progress:` ; intégration de la configuration unifiée avec une validation stricte du schéma (tolérance pour les nombres/booléens entre guillemets provenant des outils de gestion des appareils mobiles), ainsi que des rapports d'erreur JSON détaillés.

### Améliorations des bannières

L'argument `--bannerimage` prend désormais en charge les couleurs unies et les dégradés, en plus des fichiers image.

**Bannière de couleur unie :**

```sh
dialog --bannerimage "colour=accent"
dialog --bannerimage "colour=#0066CC"
dialog --bannerimage "colour=blue,nogradient"   # disable the default gradient overlay
```

Par défaut, un dégradé subtil est appliqué. Ajoutez `,nogradient` pour le désactiver.

**Bannière avec dégradé de couleurs multiples :**

```sh
dialog --bannerimage "gradient=red,orange,yellow"
dialog --bannerimage "gradient=red,orange,yellow:angle=135"
```

Les couleurs sont des noms ou des valeurs hexadécimales séparés par des virgules. Le suffixe optionnel `:angle=<degrees>` définit la direction du dégradé (0 = de bas en haut, 90 = de gauche à droite, 180 = de haut en bas ; la valeur par défaut est 90).

Les mêmes mots-clés `colour=` et `gradient=` fonctionnent également pour les images `--background` (marques d'eau).

### Améliorations apportées aux titres

**Argument concernant les sous-titres (à utiliser avec `--title` et `--bannertitle`).**

`--subtitle` vous permet d'ajouter une sous-titre en dessous du titre principal. Cela peut être utile pour fournir un contexte supplémentaire ou des instructions à l'utilisateur.

```sh
dialog --title "Main Title" --subtitle "This is a subtitle"
```

Le texte de la sous-titre est mis en forme avec les mêmes propriétés de police que le titre, mais avec une opacité de 75 %. Lorsqu'une image de bannière est utilisée, la sous-titre adopte également le style du texte de la bannière (couleur blanche, effet d'ombre). `--bannertext enable`

**Décalage de la police du titre**

`--titlefont` accepte désormais un paramètre `offset=<float>` qui permet de déplacer verticalement le texte du titre à l'intérieur de son conteneur. Ceci est utile lorsqu'on utilise des images de bannière avec du texte superposé, mais peut également être utilisé dans des boîtes de dialogue classiques pour ajuster finement le positionnement du titre.

```sh
dialog --titlefont "size=36,offset=-10"
```
### Kit de construction / Jeu de construction
Améliorations majeures du mode `--builder` :
- **Exporter** la conception actuelle au format **JSON** et vers une **commande** à exécuter en ligne.
- **Sources Markdown** — Définir le message/la boîte d'information à partir d'un **`.md` fichier ou d'une URL** ; le générateur charge le contenu pour l'aperçu en direct, tandis que les exports font référence au fichier/à l'URL.
- Une option permettant de choisir une image pour l'arrière-plan de l'écran est apparue dans le panneau des fenêtres.
- Glisser-déposer pour réorganiser les champs de texte, les cases à cocher et les éléments de liste (maintenant basés sur une liste avec des poignées de glissement, comme pour le panneau des images).
- **Éditeur de symboles de boutons structuré** — Permet de modifier le nom, la position, le mode de rendu, la taille et la couleur/palette des symboles de boutons, avec des contrôles individuels pour chaque paramètre, et offre une **prévisualisation en direct et fixe** des symboles de boutons.
- Un sélecteur d'icônes SF-Symbol partagé, accessible depuis les panneaux d'icônes, de liste et de cases à cocher ; le titre de la bannière est désormais inclus dans l'exportation ; l'icône du dock est affichée lorsque l'on est en mode création.

### Autres nouvelles options
- **Fond d'écran** — afficher une image en arrière-plan des fenêtres de dialogue via `--screenbackground` (#655).
- **Largeur de la zone d'informations** — Définir la largeur de la zone de texte de la zone d'informations indépendamment de l'icône (n° 665).
- **Prise en charge des fichiers partiels par aria2** — `cacheExtensions` est un tableau configurable qui permet de marquer les éléments comme étant "en cours de téléchargement" (par défaut : `download`, `pkg`, `dmg` ; ajoutez `aria2` pour aria2). (#617).

### Arguments non documentés précédemment

Les arguments suivants existaient dans les versions précédentes, mais n'étaient pas documentés. Une aide est désormais disponible via `--help <argument>` pour chacun d'eux :

| Argument | Description |
|---|---|
| `--helpalignment [left\|centre\|right]` | Définit l'alignement du texte du message affiché dans la fenêtre d'aide |
| `--helpsheetbuttontext <text>` | Définit le libellé du bouton de fermeture sur la feuille d'aide (par défaut : `OK`). |
| `--iconalttext <text>` | Étiquette d'accessibilité pour l'icône de la boîte de dialogue |
| `--bannerheight <num>` | Définit la hauteur de la zone de l'image de bannière en points |
| `--selectstyle [list\|radio\|searchable\|multiselect]` | Style d'affichage global pour toutes les listes déroulantes |
| `--progresstextalignment [left\|right]` | Alignement horizontal du texte de la barre de progression (par défaut : centré). |
| `--verbose` | Activer la sortie détaillée des journaux vers la sortie d'erreur standard (stderr) |
| `--eula` | Afficher le message en mode de licence (police à chasse fixe, avec défilement). |
| `--alwaysreturninput` | Retourner les entrées utilisateur pour tous les codes de sortie, et non pas seulement pour le code de sortie 0 |
| `--hidetimer` | Masquer l'indicateur de compte à rebours pendant les transitions automatiques du diaporama |
| `--listfonts` | Afficher tous les noms de polices disponibles sur la sortie standard |

### Corrections de bugs

- **Correction du problème #632** : Le menu déroulant de sélection multiple affiche correctement les étiquettes sélectionnées, dans un format de liste défilante
- Le chargement de fichiers ou d'URL ne génère plus d'erreurs lorsqu'il s'agit de chemins de fichiers inexistants (#654).
- La fonction de "mini-aperçu" affiche désormais du texte structuré au lieu de texte en ligne (#677) ; la taille a été ajustée pour macOS 26 (Tahoe) et les versions ultérieures (#649).
- Vérifier le **paramètre prédéfini 2** : effectue un suivi automatique de l'installation en cours (#565) ; respecte les statuts et les textes de progression personnalisés (#571) ; le sous-titre de l'en-tête est récupéré depuis `message` (#670).
- Inspectez : **`appearance: dark`** est désormais pris en compte lorsqu'il est défini dans le format JSON en mode "inspect".

### Modifications et suppressions
- L'envoi de notifications via **`Dialog.app` directement (sans `--style`) est obsolète** ; utilisez plutôt `--style alert` / `--style banner` ; l'utilisation de cette méthode ancienne génère un avertissement sur la sortie d'erreur standard.
- Les commandes `stub` `--inspect-schema` et `stub` `--schema-validate` ont été supprimées.
