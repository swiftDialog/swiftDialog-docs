## Novidades no swiftDialog versão 3.1.0

### Fluxo de trabalho (Diálogos com várias etapas).

A versão 3.1.0 do swiftDialog introduz o **Workflow**, um novo e poderoso recurso para a criação de diálogos com múltiplas etapas, a partir de uma única configuração em formato JSON.

- Defina um array de páginas de fluxo de trabalho usando a chave `workflow` no seu arquivo JSON, onde cada página terá seu próprio título, mensagem, ícone e campos de entrada
- Os usuários podem navegar para frente e para trás entre os elementos, e os dados inseridos são mantidos durante a navegação
- Após a conclusão, os dados de entrada de todos os cartões são combinados e retornados como uma única saída em formato JSON
- As propriedades de configuração global (definidas fora do array `cards`) funcionam como valores padrão, que podem ser substituídos individualmente para cada cartão
- Um novo recurso `--onadvance` permite que um script do shell seja executado quando o usuário avança entre os cartões. O script recebe o índice do cartão atual, o ID do cartão e a entrada do usuário via stdin, tudo em formato JSON, e pode impedir o avanço encerrando a execução com um código diferente de zero
- A validação dos campos obrigatórios é realizada para cada cartão individualmente, antes de prosseguir
- A barra de botões se adapta automaticamente (Voltar / Próximo / Concluir) com base na posição do cartão

As páginas de fluxo de trabalho também podem ter ramificações com base na interação do usuário (seleção em menus suspensos ou estado de caixas de seleção), sem a necessidade de scripts de retorno, e o texto dos botões "Próximo/Anterior" pode ser personalizado através de `--nextbuttontext` / `--previousbuttontext`.

Consulte a seção "Fluxo de Trabalho" ](/pt-br/advanced/workflows) para a documentação completa.

### Notificações

> ⚠️ **Observação:** A partir da versão 26.4 do macOS, a alteração do ícone do pacote Dialog.app para definir o ícone de notificação pode não funcionar como esperado. As notificações simuladas podem ajudar a resolver esse problema para certos tipos de notificação

#### Pacotes de aplicativos com alertas e banners

As notificações agora são entregues por aplicativos auxiliares específicos (`Dialog Alert.app` e `Dialog Banner.app`), em vez do próprio aplicativo Dialog.app.

- Aplicativos separados para notificações no estilo "alerta" e "banner", garantindo a apresentação correta das notificações no macOS
- Aplicativos auxiliares são incluídos no pacote `Dialog.app/Contents/Helpers/` e são automaticamente executados pelo lançador de linha de comando `dialog` quando `--style alert` ou `--style banner` são usados em conjunto com `--notification`
- O aviso "Aprovar Notificações" agora permanece visível até que seja descartado — ele não desaparece automaticamente
- Novos ícones para os aplicativos auxiliares de notificação

> **Aviso de Descontinuação:** O envio de notificações diretamente através de `Dialog.app` (sem `--style alert` ou `--style banner`) está descontinuado. Um aviso agora é exibido em `stderr` sempre que esse método antigo é detectado. Esse comportamento será removido em uma versão futura, e as notificações sem um estilo especificado serão exibidas por padrão como banners, utilizando a função auxiliar `Dialog Banner.app`.

#### Notificações Falsas

As notificações personalizadas são janelas com o estilo de notificações criadas diretamente pelo swiftDialog, e não pelas notificações do sistema macOS. Elas aparecem deslizando a partir da borda direita da tela e imitam a aparência das notificações nativas, com um fundo translúcido.

> As notificações "pseudo" não são notificações do sistema. Elas desaparecem assim que são descartadas e não seguem as regras padrão das notificações do sistema macOS.

[Mais informações](https://beta.swiftdialog.app/advanced/notifications/#pseudo-notifications)

### Modo de Inspeção
Uma atualização significativa do modo de inspeção (que foi lançado na versão 3.0.x):

- Painéis de conformidade — Interface com design baseado em arquivos plist, com um `ComplianceAggregatorService`, blocos de conteúdo `compliance-summary` / `findings-list` compartilhados e células "bento" com preenchimento automático.
- **Motor de cadência com controle de acesso** — as mensagens avançam apenas quando um atributo monitorado é satisfeito, com opção de acionamento por comunicação entre processos e tempos limite para cada entrada (`stepType: "cadence"`); além de um **indicador de status em formato de carrossel** (similar ao DEPNotify, com ícones que representam "concluído", "ativo" ou "pendente").
- **`managedpref` atributo** — a configuração de cadência/gatilho pode ser aplicada no nível do dispositivo ou do usuário `/Library/Managed Preferences/<domain>.plist`.
- **`ManagedValueRef`** — A personalização da marca para cada usuário extrai as cores e informações da marca de diferentes domínios de configuração do MDM.
- **Aparência forçada** — `appearance` A chave de configuração "config key" força a aparência clara ou escura da janela de inspeção, independentemente das configurações do sistema operacional (#669).
- **Redesign da configuração 3:** (bloco principal, rodapé, barra de progresso da marca com design mais fino); **logotipo da marca no rodapé, fixo e com uma versão para o modo escuro;** **descrições individuais para cada item** nas configurações 1/2/3/5/6 (nº 663); badge de informações com a cor da marca, com design unificado.
- **IPC / sessões** — Descoberta de sessões por PID (`--published-sessions-dir` publica `<pid>.json`); o JSON da sessão é enriquecido com os caminhos `resultFile`, `readinessFile` e `eventFile`.
- **Otimização (PR #684):** indicador de carregamento único no cabeçalho + pontos de status estáticos para instalações simultâneas; imagens de destaque baseadas em arquivos, exibidas em sua totalidade (sem cortes); transições suaves e nítidas no Preset 5; aprimoramento do processo de integração do Preset 5 (com texto mais claro e menus suspensos centralizados); grade de espaçamento unificada de 12 pontos nos Presets 1–3 e no seletor de papel de parede; adição de indicadores de prontidão nos Presets 1/2/3; registro de eventos de interação em tempo real para menus suspensos, botões de rádio e caixas de seleção; visualização de relatório do Preset 4 através de `progressMode "report"` e acompanhamento do progresso externo através do comando IPC `progress:`; sistema de configuração unificado com validação estrita do esquema (compatível com números/booleanos formatados em ferramentas de gerenciamento de dispositivos móveis), com relatórios detalhados de erros em formato JSON.

### Melhorias para banners

O `--bannerimage` argumento agora suporta opções de cores sólidas e gradientes, além de arquivos de imagem.

**Banner de cor sólida:**

```sh
dialog --bannerimage "colour=accent"
dialog --bannerimage "colour=#0066CC"
dialog --bannerimage "colour=blue,nogradient"   # disable the default gradient overlay
```

Por padrão, é aplicada uma sobreposição de gradiente sutil. Adicione `,nogradient` para desativá-la.

**Banner com gradiente de cores:**

```sh
dialog --bannerimage "gradient=red,orange,yellow"
dialog --bannerimage "gradient=red,orange,yellow:angle=135"
```

As cores são nomes ou valores hexadecimais, separados por vírgulas. O sufixo `:angle=<degrees>`, que é opcional, define a direção do gradiente (0 = de baixo para cima, 90 = da esquerda para a direita, 180 = de cima para baixo; o padrão é 90).

As mesmas palavras-chave `colour=` e `gradient=` também funcionam para imagens de `--background` (marca d'água).

### Melhorias no título

Argumento para legenda (a ser utilizado com `--title` e `--bannertitle`)

`--subtitle` permite que você adicione uma legenda abaixo do título principal. Isso é útil para fornecer contexto adicional ou instruções ao usuário.

```sh
dialog --title "Main Title" --subtitle "This is a subtitle"
```

O texto do subtítulo é formatado com as mesmas propriedades de fonte que o título, mas com uma opacidade de 75%. Quando uma imagem de banner é utilizada, o subtítulo também adota o estilo do texto do banner (cor branca e sombra). `--bannertext enable`

**Deslocamento da fonte do título**

`--titlefont` Agora aceita um parâmetro `offset=<float>` para ajustar verticalmente o texto do título dentro de seu contêiner. Isso é útil ao usar imagens de banner com texto de título sobreposto, mas também pode ser usado em diálogos comuns para ajustar com precisão o posicionamento do título.

```sh
dialog --titlefont "size=36,offset=-10"
```
### Kit de construção / Conjunto de montagem
Melhorias significativas no modo `--builder`:
- **Exporte** o design atual para o formato **JSON** e para uma chamada de linha de comando.
- **Fontes em Markdown:** — defina a mensagem/caixa de informações a partir de um **`.md` arquivo ou URL**; o construtor carrega o conteúdo para a visualização em tempo real, enquanto as exportações fazem referência ao arquivo/URL.
- A opção de imagem de fundo da tela apareceu no painel de configurações do Windows.
- **Arraste e reorganize** para campos de texto, caixas de seleção e itens de lista (agora com base em listas e com indicadores de arrasto, assim como no painel de imagens).
- **Editor estruturado para ícones de botões** — Permite editar o nome do ícone (SF Symbol), a posição, o modo de renderização, o tamanho e a cor/paleta, com controles individuais, e oferece uma **previsualização em tempo real** dos ícones dos botões.
- Seletor de ícones SF-Symbol compartilhado, disponível nas seções de ícones, lista e caixa de seleção; o título do banner agora é incluído na exportação; o ícone da barra de dock é exibido quando o programa está no modo de edição.

### Outras opções inovadoras
- **Fundo da tela** — exiba uma imagem atrás das janelas de diálogo através de `--screenbackground` (#655).
- **Largura da caixa de informações** — ajuste o tamanho da área de texto da caixa de informações de forma independente do ícone (nº 665).
- **aria2 partial-file support** — `cacheExtensions` is a configurable array marking items as "downloading" (defaults `download`, `pkg`, `dmg`; add `aria2` for aria2) (#617).

### Argumentos não documentados anteriormente

Os seguintes argumentos existiam em versões anteriores, mas não estavam documentados. Agora, uma ajuda textual está disponível para cada um deles, através de `--help <argument>`.

| Argumento | Descrição |
|---|---|
| `--helpalignment [left\|centre\|right]` | Define o alinhamento do texto da mensagem exibida na tela de ajuda |
| `--helpsheetbuttontext <text>` | Define o texto do botão de "fechar" na tela de ajuda (padrão: `OK`). |
| `--iconalttext <text>` | Rótulo de acessibilidade para o ícone da janela de diálogo |
| `--bannerheight <num>` | Define a altura da área da imagem do banner em pontos |
| `--selectstyle [list\|radio\|searchable\|multiselect]` | Estilo de exibição global para todas as listas de seleção |
| `--progresstextalignment [left\|right]` | Alinhamento horizontal do texto da barra de progresso (padrão: centralizado). |
| `--verbose` | Habilite a saída detalhada dos logs para o fluxo de erro padrão (stderr) |
| `--eula` | Exibir a mensagem no modo de Termos de Uso (fonte monoespaçada e com barra de rolagem). |
| `--alwaysreturninput` | Retornar a entrada do usuário para todos os códigos de saída, e não apenas para o código de saída 0 |
| `--hidetimer` | Oculte o indicador de contagem regressiva durante as transições automáticas do carrossel de imagens |
| `--listfonts` | Imprima todos os nomes de fontes disponíveis na saída padrão |

### Correções de bugs

- **Correção para o problema #632** — O menu suspenso de seleção múltipla exibe corretamente as tags selecionadas em um layout de fluxo com barra de rolagem
- O carregamento de arquivos/URLs não gera mais erros ao tentar acessar caminhos de arquivos que não existem (#654).
- A visualização compacta agora exibe texto formatado em vez de texto embutido (#677); o tamanho foi ajustado para versões do macOS 26 (Tahoe) e posteriores (#649).
- Verifique a **Predefinição 2**: acompanha automaticamente a instalação ativa (#565); respeita as configurações personalizadas e o texto de status e progresso (#571); o subtítulo do cabeçalho é obtido de `message` (#670).
- Verificar: **`appearance: dark`** agora é reconhecido quando configurado no modo de verificação no formato JSON.

### Alterações e Descontinuações
- Enviar notificações diretamente via **`Dialog.app` (sem `--style`) está obsoleto** — utilize `--style alert` / `--style banner`; o uso antigo gera um aviso no stderr.
- Removidos os comandos "stub" `--inspect-schema` e "stub" `--schema-validate`.
