## O que há de novo


### 🚨 Mudança significativa 🚨

O swiftDialog 3.0 requer o sistema operacional **macOS 15** ou uma versão mais recente

Se você precisar dar suporte ao macOS 14 ou versões anteriores, utilize a versão [v2.5.6](https://github.com/swiftDialog/swiftDialog/releases/tag/v2.5.6)

### Nova documentação

Toda a documentação está agora disponível em [https://swiftdialog.app](https://swiftdialog.app/getting-started/introduction/)


### Suporte para o estilo visual do macOS 26

Esta versão terá a aparência do macOS 26 quando executada no macOS 26, e a aparência do macOS 15 quando executada no macOS 15

Existe um novo ícone, com formato "squircle", que se alinha ao estilo de marca macOS 26 e evita que ele seja classificado como um ícone "squircle" inadequado.

O texto padrão antigo, utilizado para os campos de "Título" e "Mensagem" com a mensagem "Mensagem importante", foi removido. Deixar os campos de título ou mensagem em branco resultará em mensagens e títulos vazios. O ícone padrão agora utiliza o recurso AppIcon integrado, em vez de um símbolo SF

### Novo `--inspect-mode`

O modo "Inspeção" é um novo recurso integrado que permite o monitoramento em tempo real dentro do sistema de arquivos do macOS. Ele acompanha o status do sistema de arquivos (utilizando a API FSEvents da Apple), ao mesmo tempo que monitora instalações de aplicativos e examina pastas, arquivos e conteúdos de arquivos plist para visualizar verificações de conformidade. Este recurso foi projetado especificamente para uso durante o processo de registro de dispositivos, implantação de software e auditoria de conformidade

### Alterações em `/usr/local/bin/dialog`

`/usr/local/bin/dialog` agora é um link para um arquivo binário compilado `dialogcli`, escrito em Swift. Anteriormente, isso era um script de shell que lidava com o processamento de linha de comando e o lançamento do pacote de aplicativos Dialog.app.

A utilitário de linha de comando integrado `dialogcli` determina de forma inteligente a localização do pacote de aplicativos `Dialog.app` durante a execução, tornando o aplicativo Dialog relocável. Para executar, utilize o comando `/path/to/Dialog.app/Contents/MacOS/dialogcli`

Para esta versão inicial, o programa geralmente desempenha a mesma função que o script de shell, mas será expandido ao longo do tempo. O suporte para a execução direta do arquivo binário `Dialog.app/Contents/MacOS/Dialog` será removido em uma versão futura

⚠️ _Observação Importante:_ Nesta versão, ao executar `Dialog.app/Contents/MacOS/Dialog` diretamente, a quantidade e a ordem dos argumentos são importantes. Para facilitar a leitura, especifique as opções (argumentos sem parâmetros, como `--ontop`) no _final_ do seu comando.

### Modos de construção

`--builder` mode is for assistance when constructing regular dialogs and has been updated with some fixes for broken functionality and updates for some of the new layouts. Documentation [here](https://swiftdialog.app/builder/builder/)

Execute o comando `--inspect-mode` sem argumentos para abrir a ferramenta de configuração de exemplo

### Outras adições

 - Adicionar suporte para especificar uma localização exata na tela usando a opção --position x,y. #452
 - Adicionar suporte para ações em itens de lista. As ações são limitadas à abertura de URLs. #472
 - Adicionar uma opção de caminho de arquivo ao campo de seleção de arquivos para definir o caminho inicial do arquivo. Por padrão, utiliza o diretório inicial do usuário caso essa opção não seja utilizada. #451
 - Adicione a opção "iconalpha" à lista de itens (listitems) #508
 - Adicione um componente opcional `--loghistory` para uso com `--displaylog` #539
 - Adicionado uma barra de progresso linear personalizada que indica um estado indeterminado (isso foi necessário, pois a barra de progresso linear do macOS 26 não anima corretamente).
 - `--image` e `--icon` agora podem aceitar múltiplos valores como uma única lista separada por vírgulas, por exemplo: `--image "/path/image1.png","/path/image2.png","/path/image3.png" #536`
 - Adicionada `searchable` opção aos menus suspensos
   - Exemplo:
   ```
   dialog --selecttitle "Search Me",searchable --selectvalues "Apple,Banana,Cherry,Date,Elderberry,Fig,Grape,Honeydew,Kiwi,Lemon,Mango,Nectarine,Orange,Papaya,Quince,Raspberry,Strawberry,Tangerine,Ugli Fruit,Watermelon"
   ```
 - Adicionado `--sound` para reproduzir um som na inicialização. Aceita arquivo ou URL
   - exemplo `dialog --sound /System/Library/Sounds/Glass.aiff`
   - Se você inserir um arquivo de áudio muito longo, adicione a opção `--showsoundcontrols`.
 - Adicionado suporte para GIFs animados (finalmente).
- Permitir que os itens da lista sejam selecionáveis (um ou vários). #465
   - Novo argumento `--enablelistselect` que permite a seleção de itens da lista ao clicar. O status da seleção é enviado para a saída padrão (stdout) como `"<title>" : "<status"`
 - Agora, os botões podem exibir símbolos e o tamanho do texto é ajustável
   - Novos argumentos `--button1symbol` `--button2symbol` `--infobuttonsymbol`. Aceita o nome de um símbolo SF como valor. Propriedades opcionais: posição, tamanho, estilo, cor. Consulte `--help button1symbol` para mais informações.
     - Exemplo: `--button1symbol sunrise.fill,multicolour,leading`
   - O novo argumento `--buttontextsize` aceita um valor numérico para definir o tamanho desejado do texto
   - Agora, é possível especificar valores para o texto dos botões como `nil` para desabilitar a exibição do texto
 - Ativar o uso do botão 1 com estilo empilhado e temporizador #520
 - O ícone do swiftDialog pode ser exibido na barra de dock usando `--showdockicon`
   - O ícone da barra de tarefas pode ser configurado para exibir uma imagem personalizada, utilizando `--dockicon <img>`
   - O ícone da barra de aplicativos pode ter um indicador numérico `--dockbadge <text>`
   - A visibilidade do ícone e o indicador (badge) podem ser atualizados através de um arquivo de configuração
   - O ícone da barra de tarefas pode ser configurado para "pular" – no modo normal, ele dá um pulo; no modo crítico, ele pula várias vezes
 - As transições de símbolos SF agora são animadas entre tipos de símbolos compatíveis
 - Adicionada a opção `--hideotherapps`: ao ser iniciada, a função swiftDialog fará com que todos os outros aplicativos sejam ocultados
 - Adicionado suporte para cores de texto embutidas, utilizando o formato `:colour[text]`. Por exemplo: `"Text can be :blue[blue] or :red[red]"`
   - Suportado em qualquer área de texto em formato Markdown, assim como em `--title` e `--bannertitle`
 - Adicionado suporte para alinhamento de texto à esquerda/direita para o título e o texto de progresso
   - `--titlefont alignment=left`
   - `--progresstextalignment left`
