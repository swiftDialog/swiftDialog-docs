## ¿Qué hay de nuevo en swiftDialog 3.1.0?

### Flujo de trabajo (diálogos con múltiples pasos).

swiftDialog 3.1.0 introduce **Workflow**, una nueva y potente función para crear diálogos con múltiples pasos a partir de una única configuración JSON.

- Defina un arreglo de páginas de flujo de trabajo utilizando la clave `workflow` en su archivo JSON, donde cada página tenga su propio título, mensaje, icono y campos de entrada
- Los usuarios pueden navegar **hacia adelante y hacia atrás** entre las diferentes secciones, y la información ingresada se mantiene durante la navegación
- Una vez finalizado el proceso, la información combinada de todas las tarjetas se devuelve como una única salida en formato JSON
- Las propiedades de configuración global (definidas fuera del `cards` array) actúan como valores predeterminados, que pueden ser modificados individualmente para cada tarjeta
- Nuevo `--onadvance` argumento que permite ejecutar un script de shell cuando el usuario avanza entre las tarjetas. El script recibe el índice de la tarjeta actual, el identificador de la tarjeta y la entrada del usuario a través de la entrada estándar (stdin) en formato JSON, y puede impedir el avance saliendo con un código de error distinto de cero
- La validación de los campos obligatorios se realiza para cada tarjeta antes de continuar
- La barra de botones se adapta automáticamente (Atrás / Siguiente / Finalizar) según la posición de la tarjeta

Las páginas de flujo de trabajo también pueden tener **ramas** basadas en la entrada del usuario (selección de un menú desplegable o estado de una casilla de verificación), sin necesidad de un script de llamada, y el texto de los botones "Siguiente/Anterior" se puede personalizar a través de `--nextbuttontext` / `--previousbuttontext`.

Consulte [Flujo de trabajo](/es/advanced/workflows)] para obtener la documentación completa.

### Notificaciones

> ⚠️ **Nota:** A partir de macOS 26.4, la función de establecer el icono del paquete de la aplicación Dialog.app para configurar el icono de notificación podría no funcionar como se espera. Las notificaciones simuladas podrían ayudar a solucionar este problema para ciertos tipos de notificaciones

#### Paquetes de aplicaciones con alertas y banners

Las notificaciones ahora se entregan a través de aplicaciones auxiliares específicas (`Dialog Alert.app` y `Dialog Banner.app`) en lugar de la propia aplicación Dialog.app.

- Aplicaciones separadas para las notificaciones de tipo "alerta" y "banner", lo que garantiza la correcta presentación de las notificaciones en macOS
- Las aplicaciones de utilidad se incluyen dentro de `Dialog.app/Contents/Helpers/` y son invocadas automáticamente por el lanzador de línea de comandos `dialog` cuando `--style alert` o `--style banner` se utilizan junto con `--notification`
- La alerta "Aprobar notificaciones" ahora permanece visible hasta que se desactive manualmente; ya no se cierra automáticamente
- Nuevos iconos para las aplicaciones de asistencia de notificaciones

> **Aviso de obsolescencia:** El envío de notificaciones directamente a través de `Dialog.app` (sin utilizar `--style alert` o `--style banner`) está obsoleto. Ahora se muestra una advertencia en `stderr` cuando se detecta este uso heredado. Este comportamiento se eliminará en una futura versión, y las notificaciones que no especifiquen un estilo se mostrarán por defecto como banners, utilizando la función auxiliar `Dialog Banner.app`.

#### Notificaciones simuladas

Las notificaciones personalizadas son ventanas con el estilo de las notificaciones creadas directamente por swiftDialog, en lugar de ser las notificaciones del sistema macOS. Aparecen deslizándose desde el borde derecho de la pantalla y emulan la apariencia de las notificaciones nativas, con un fondo translúcido.

> Las notificaciones "pseudo" no son notificaciones del sistema. No permanecen visibles una vez que se descartan y no siguen las normas estándar para las notificaciones del sistema de macOS.

[Más información](https://beta.swiftdialog.app/advanced/notifications/#pseudo-notifications)

### Modo de inspección
Una actualización importante del modo de inspección (que se introdujo en la versión 3.0.x):

- **Paneles de control de cumplimiento** — Interfaz de usuario basada en archivos plist, con una barra de herramientas `ComplianceAggregatorService`, bloques de contenido compartidos `compliance-summary`/`findings-list` y celdas "bento" con enlace automático.
- **Motor de cadencia con control de acceso** — los mensajes avanzan solo cuando se cumple un atributo monitorizado, con una opción de control de procesos inter-proceso y tiempos de espera configurables por entrada (`stepType: "cadence"`); además, incluye un **indicador de estado tipo carrusel** (fila de iconos que muestra el estado: completado, activo, pendiente, similar a DEPNotify).
- **`managedpref` Atributo:** — La cadencia/el control de acceso puede aplicarse a `/Library/Managed Preferences/<domain>.plist` (alcance del dispositivo o del usuario).
- **`ManagedValueRef`** — La personalización por inquilino extrae los colores y elementos de marca de diferentes dominios de carga útil de MDM.
- **Apariencia forzada** — `appearance` La clave de configuración "forced_appearance" obliga a que la ventana de inspección tenga una apariencia clara u oscura, independientemente de la configuración del sistema operativo (#669).
- **Rediseño de la opción predefinida 3:** (bloque principal, pie de página, línea de progreso de la marca con diseño minimalista); **logotipo de la marca en el pie de página, con una versión para el modo oscuro;** **descripciones individuales** para las opciones predefinidas 1, 2, 3 y 5, 6 (número de referencia: #663); distintivo de información con el color de la marca.
- **IPC / sesiones** — Descubrimiento de sesiones por PID (`--published-sessions-dir` publica `<pid>.json`); el JSON de la sesión se enriquece con las rutas `resultFile`, `readinessFile` y `eventFile`.
- **Mejora (PR #684):** indicador de carga único en la parte superior + puntos de estado estáticos para instalaciones simultáneas; imágenes de cabecera basadas en archivos (sin recortar); transiciones nítidas para el Preset 5; mejora en la secuencia de inicio del Preset 5 (énfasis en el texto, menús desplegables centrados); cuadrícula de espaciado unificada de 12 puntos para los Presets 1–3 y el selector de fondos de pantalla; se ha añadido un indicador de estado de preparación para los Presets 1/2/3; registro de eventos de interacción en tiempo real para menús desplegables, botones de opción y casillas de verificación; vista de informe del Preset 4 a través de `progressMode "report"` y seguimiento del progreso externo a través del comando IPC `progress:`; configuración unificada con validación estricta del esquema (compatible con números y booleanos entre comillas provenientes de herramientas de administración de dispositivos móviles), con informes de errores detallados en formato JSON.

### Mejoras para el banner

El `--bannerimage` argumento ahora admite opciones de color sólido y degradados, además de archivos de imagen.

**Banner de color sólido:**

```sh
dialog --bannerimage "colour=accent"
dialog --bannerimage "colour=#0066CC"
dialog --bannerimage "colour=blue,nogradient"   # disable the default gradient overlay
```

Por defecto, se aplica una sutil superposición de degradado. Para desactivarla, agregue `,nogradient`.

**Banner con degradado de múltiples colores:**

```sh
dialog --bannerimage "gradient=red,orange,yellow"
dialog --bannerimage "gradient=red,orange,yellow:angle=135"
```

Los colores son nombres o valores hexadecimales separados por comas. El sufijo opcional `:angle=<degrees>` establece la dirección del degradado (0 = de abajo hacia arriba, 90 = de izquierda a derecha, 180 = de arriba hacia abajo; el valor predeterminado es 90).

Las mismas palabras clave `colour=` y `gradient=` también funcionan para las imágenes `--background` (marcas de agua).

### Mejoras en el título

**Argumento del subtítulo (para usar con `--title` y `--bannertitle`)**

`--subtitle` le permite agregar un subtítulo debajo del título principal. Esto es útil para proporcionar información adicional o instrucciones al usuario.

```sh
dialog --title "Main Title" --subtitle "This is a subtitle"
```

El texto del subtítulo se formatea con las mismas propiedades de fuente que el título, pero con una opacidad del 75%. Cuando se utiliza una imagen de encabezado, el subtítulo también adopta el estilo de texto de la imagen (color blanco, sombra). `--bannertext enable`

**Desplazamiento de la fuente del título.**

`--titlefont` Ahora acepta un parámetro `offset=<float>` para ajustar verticalmente el texto del título dentro de su contenedor. Esto es útil al utilizar imágenes de encabezado con texto superpuesto, pero también se puede utilizar en diálogos estándar para ajustar con precisión la posición del título.

```sh
dialog --titlefont "size=36,offset=-10"
```
### Kit de construcción / Juego de construcción
Mejoras significativas en el modo `--builder`:
- **Exportar** el diseño actual a formato **JSON** y a una línea de comandos.
- **Fuentes de Markdown:** Permite establecer el mensaje o la información que se mostrará a partir de un **`.md` archivo o una URL**. El generador carga el contenido para la vista previa, mientras que las exportaciones hacen referencia al archivo/URL.
- Se ha añadido una opción para seleccionar una imagen de fondo en la ventana.
- **Arrastrar y soltar para reordenar** en campos de texto, casillas de verificación y elementos de lista (ahora basado en listas, con indicadores de arrastre, para que coincida con el panel de imágenes).
- **Editor estructurado de símbolos para botones** — Permite configurar el nombre del símbolo SF, su posición, modo de renderizado, tamaño y color/paleta, a través de controles individuales, con una **vista previa en tiempo real y fija** de los símbolos de los botones.
- Se ha implementado un selector de iconos SF-Symbol compartido, accesible desde los paneles de iconos, listas y casillas de verificación. El título del banner ahora se incluye en la exportación. El icono de la barra de aplicaciones se muestra cuando se está en modo de edición.

### Otras opciones nuevas
- **Fondo de pantalla:** Mostrar una imagen detrás de las ventanas de diálogo a través de `--screenbackground` (#655).
- **Ancho de la caja de información:** Permite ajustar el tamaño del área de texto de la caja de información de forma independiente del icono (número de referencia: 665).
- **aria2 partial-file support** — `cacheExtensions` is a configurable array marking items as "downloading" (defaults `download`, `pkg`, `dmg`; add `aria2` for aria2) (#617).

### Argumentos no documentados previamente

Los siguientes argumentos existían en versiones anteriores, pero no estaban documentados. Ahora, se dispone de una ayuda para cada uno de ellos a través de `--help <argument>`.

| Argumento | Descripción |
|---|---|
| `--helpalignment [left\|centre\|right]` | Establece la alineación del texto del mensaje que se muestra en la hoja de ayuda |
| `--helpsheetbuttontext <text>` | Establece la etiqueta del botón de "cerrar" en la hoja de ayuda (por defecto: `OK`). |
| `--iconalttext <text>` | Etiqueta de accesibilidad para el icono del diálogo |
| `--bannerheight <num>` | Establece la altura, en puntos, del área de la imagen del banner |
| `--selectstyle [list\|radio\|searchable\|multiselect]` | Estilo de visualización global para todas las listas desplegables |
| `--progresstextalignment [left\|right]` | Alineación horizontal del texto de la barra de progreso (por defecto: centrado). |
| `--verbose` | Habilitar la salida detallada de los registros a la salida de error estándar |
| `--eula` | Mostrar el mensaje en modo de licencia de usuario final (con fuente de ancho fijo y posibilidad de desplazamiento). |
| `--alwaysreturninput` | Devuelva la entrada del usuario para todos los códigos de salida, no solo para el código de salida 0 |
| `--hidetimer` | Ocultar el indicador de cuenta regresiva durante las transiciones automáticas del carrusel de imágenes |
| `--listfonts` | Imprima todos los nombres de fuentes disponibles en la salida estándar |

### Corrección de errores

- **Corrección del problema #632** — El menú desplegable de selección múltiple muestra correctamente las etiquetas seleccionadas en un diseño adaptable con barra de desplazamiento
- La carga de archivos o URL ya no genera errores cuando se utilizan **rutas de archivo inexistentes** (#654).
- La función de "vista previa" ahora muestra texto estructurado en lugar de texto en línea (#677); se han realizado ajustes en el tamaño para versiones de macOS 26 (Tahoe) y posteriores (#649).
- Inspeccionar **Preajuste 2**: realiza un seguimiento automático de la instalación activa (#565); respeta el estado personalizado y el texto de progreso (#571); el subtítulo del encabezado se obtiene de `message` (#670).
- Inspeccionar: **`appearance: dark`** ahora se reconoce cuando se utiliza en formato JSON en el modo de inspección.

### Cambios y obsolescencias
- Enviar notificaciones a través de **`Dialog.app` directamente (sin `--style`) está obsoleto**; utilice `--style alert` / `--style banner`; el uso heredado genera una advertencia en la salida de error estándar.
- Se eliminaron los comandos "stub" `--inspect-schema` y "stub" `--schema-validate`.
