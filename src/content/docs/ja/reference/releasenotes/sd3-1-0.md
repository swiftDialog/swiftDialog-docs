## swiftDialog 3.1.0 の新機能

### ワークフロー（複数ステップの対話）

swiftDialog 3.1.0では、**Workflow（ワークフロー）**という、単一のJSON設定ファイルから複数のステップを含むダイアログを構築できる、強力な新機能が導入されました。

- JSONファイル内で、`workflow` キーを使用して、ワークフローの各ページを定義します。各ページには、それぞれ独自のタイトル、メッセージ、アイコン、および入力フィールドを設定できます。
- ユーザーは、カード間を**前後に移動**することができ、移動操作を行っても入力内容は保持されます。
- すべてのカードからの入力が収集され、処理が完了すると、それらは単一のJSON形式の出力として返されます。
- グローバル設定プロパティ（配列`cards`の外で定義されるもの）は、デフォルト値として機能し、各カードごとに上書きすることができます。
- 新しい機能により、ユーザーがカード間を移動する際に、シェルスクリプトを実行できるようになりました。このスクリプトは、現在のカードのインデックス、カードID、およびユーザーからの入力をJSON形式で標準入力から受け取り、非ゼロの終了コードで終了することで、カードの移動を一時的に停止させることができます。`--onadvance`
- 各カードに対して、必須項目の入力が完了しているかどうかのチェックを行い、問題がなければ次の段階へ進みます。
- ボタンバーは、カードの位置に応じて自動的に調整され（「戻る」「次へ」「完了」ボタンなど）、適切なボタンが表示されます。

ワークフローのページは、ユーザーの入力（ドロップダウン選択やチェックボックスの状態）に基づいて、追加のスクリプトなしで分岐させることが可能です。また、「次へ」「前へ」ボタンのテキストは、`--nextbuttontext`/`--previousbuttontext`を通じてカスタマイズできます。

詳細なドキュメントについては、[Workflow](/ja/advanced/workflows)] をご参照ください。

### 通知

> ⚠️ **注意:** macOS 26.4 以降のバージョンでは、Dialog.app のバンドルアイコンを設定して通知アイコンを変更する機能が、期待通りに動作しない場合があります。この問題に対して、擬似通知が特定の種類の通知で有効な解決策となる可能性があります。

#### アラートとバナーアプリのバンドルセット。

通知は、以前はDialog.app自体が配信していましたが、現在は専用の補助アプリ（`Dialog Alert.app`および`Dialog Banner.app`）によって配信されます。

- 「アラート」と「バナー」という2種類の通知形式に対応した個別のアプリケーションを用意し、macOSの正しい通知表示形式を確実に適用します。
- 補助機能を提供するアプリケーションは、`Dialog.app/Contents/Helpers/`の中に組み込まれており、`dialog`のコマンドラインインターフェース（CLI）ランチャーが、`--style alert`または`--style banner`を`--notification`と組み合わせて使用する際に、自動的に起動されます。
- 「通知の承認」に関する警告メッセージは、ユーザーが手動で消去するまで表示され続けるようになり、自動的に消えることはありません。
- 通知ヘルパーアプリの新しいアイコンです。

> **非推奨に関するお知らせ:** `Dialog.app`を直接使用して通知を送信すること（`--style alert`または`--style banner`を使用しない場合）は、非推奨となりました。この古い方法が使用された場合、`stderr`に警告メッセージが表示されます。この動作は、今後のバージョンで削除され、スタイルが指定されていない通知は、デフォルトで`Dialog Banner.app`のユーティリティを使用してバナーとして表示されます。

#### 疑似通知

「疑似通知」とは、macOSのシステム通知ではなく、swiftDialog自体が生成する、通知のようなウィンドウのことです。画面の右端からスライドして表示され、半透明の背景素材を使用することで、ネイティブの通知と似た外観をしています。

> 疑似通知は、システムからの通知ではありません。一度閉じると消えてしまい、macOSの標準的なシステム通知のルールに従いません。

[詳細情報](https://beta.swiftdialog.app/advanced/notifications/#pseudo-notifications)

### 検査モード。
バージョン3.0.xでリリースされた「検査モード」が、大幅に改良されました。

- **コンプライアンスダッシュボード** — plistファイルで制御されるUIで、共通のコンテンツブロックと、自動的に連携されるベン Toscana形式のデータ表示領域を備えています。`ComplianceAggregatorService` `compliance-summary` `findings-list`
- **ゲート付きカデンスマネージャー** — メッセージは、監視対象の属性が満たされた場合にのみ進行します。オプションでIPC機能と、各エントリごとのタイムアウト設定が可能です (`stepType: "cadence"`)。さらに、**カレイドスコープ形式の表示** (DEPNotifyのような、完了/アクティブ/保留状態を示すアイコンの行) もサポートしています。
- **`managedpref` 属性:** カデンス/ゲーティング機能は、対象範囲がデバイスまたはユーザーのどちらかであるかを識別できます。 `/Library/Managed Preferences/<domain>.plist`
- **`ManagedValueRef`** — テナントごとに異なるブランド設定を適用するために、MDM（モバイルデバイス管理）のペイロードドメインから、ブランドの色やロゴなどの情報を取得します。
- **強制的な表示設定** — `appearance` この設定キーを使用すると、OSの設定に関わらず、インスペクターウィンドウの表示を明るいテーマまたは暗いテーマに強制的に変更できます（#669）。
- **プリセット3のデザイン変更**（ヒーローブロック、フッター、細いブランド進捗表示線）。**常に表示されるブランドロゴ**（ダークモード対応）。**各項目ごとの詳細説明**（プリセット1/2/3/5/6に対応、#663）。ブランドカラーに合わせた情報バッジの統一。
- **IPC / セッション** — per-PIDセッション検出（`--published-sessions-dir`が`<pid>.json`を公開）; セッションJSONに`resultFile`、`readinessFile`、`eventFile`パスが追加されました。
- **改善点 (プルリクエスト #684):** 同時インストール時に、ヘッダーにインジケーターを追加し、ステータスを示すドットを表示。ファイル全体を使用するヒーロー画像を採用。Preset 5のクロスフェードを改善。Preset 5のオンボーディング機能を改善し、文章を強調し、ブラウザのドロップダウンメニューを中央に配置。Preset 1～3と壁紙選択画面で、12ポイントの均一な間隔グリッドを適用。Preset 1/2/3に、準備完了を示す信号を追加。ドロップダウン/ラジオボタン/チェックボックスの操作ログをリアルタイムで記録。Preset 4のレポート表示は、`progressMode "report"`を通じて、外部からの進捗状況は、`progress:`のIPCコマンドを通じて確認可能。厳格なスキーマ検証を含む、統合された設定入力機能を実装し（MDMツールからの引用された数値/ブール値は許容）、詳細なJSON形式のエラーレポートを提供。

### バナーの機能改善。

現在、この機能は、画像ファイルに加えて、単色やグラデーションの指定もサポートしています。`--bannerimage`

**単色バナー：**

```sh
dialog --bannerimage "colour=accent"
dialog --bannerimage "colour=#0066CC"
dialog --bannerimage "colour=blue,nogradient"   # disable the default gradient overlay
```

デフォルトでは、わずかなグラデーションが適用されます。無効にするには、`,nogradient`を付与してください。

多色のグラデーションバナー。

```sh
dialog --bannerimage "gradient=red,orange,yellow"
dialog --bannerimage "gradient=red,orange,yellow:angle=135"
```

色の指定は、カンマで区切られた名前または16進数で表されます。オプションの`:angle=<degrees>`は、グラデーションの方向を設定します（0 = 下から上へ、90 = 左から右へ、180 = 上から下へ。デフォルトは90）。

同じキーワードは、`colour=`、`gradient=`だけでなく、`--background`（透かし）画像にも適用できます。

### タイトルに関する改善点。

**字幕に関する記述 (`--title` および `--bannertitle` と併用する場合)**

`--subtitle`を使用すると、メインタイトルの下にサブタイトルを追加できます。これは、ユーザーに追加の情報や指示を提供する場合に役立ちます。

```sh
dialog --title "Main Title" --subtitle "This is a subtitle"
```

字幕テキストは、タイトルと同じフォント設定を使用しますが、透明度が75%に設定されています。バナー画像が使用される場合、字幕もバナーテキストと同じスタイル（白色、影）を適用します。`--bannertext enable`

**タイトルフォントのオフセット**

`--titlefont` は、タイトルテキストをコンテナ内で垂直方向に微調整するための `offset=<float>` パラメータを受け入れるようになりました。これは、背景画像の上にタイトルテキストを重ねて表示する場合に役立ちますが、通常のダイアログボックスにおいても、タイトルテキストの位置を細かく調整する際に利用できます。

```sh
dialog --titlefont "size=36,offset=-10"
```
### 組み立て式おもちゃ / 建設キット
`--builder`モードに関する大幅な改善点：
- 現在のデザインをJSON形式でエクスポートし、また、コマンドラインからの呼び出しに対応した形式で出力します。
- **Markdownソース:** メッセージやインフォボックスを、**`.md`ファイルまたはURL**から設定します。 ビルダーは、プレビュー表示のためにコンテンツを読み込みますが、エクスポート時にはファイルまたはURLを参照します。
- ウィンドウペインに、スクリーン背景画像を設定するオプションが表示されました。
- テキストフィールド、チェックボックス、およびリスト項目において、ドラッグ操作による並び替え機能を追加しました（画像表示領域と同様に、リスト形式でドラッグハンドルを表示します）。
- **構造化されたボタンシンボルエディタ** - SF Symbolsの名前、位置、描画モード、サイズ、および色/カラースキームを、それぞれ個別のコントロールとして設定でき、ボタンシンボルの**リアルタイムプレビュー**を固定表示します。
- アイコン、リスト、チェックボックスの各パネルで、共通のSF-Symbolアイコン選択機能を使用できるようになりました。また、エクスポート時にバナーのタイトルも含まれるようになり、ビルダーモード中はドックアイコンが表示されるようになりました。

### その他の新しい選択肢。
- **画面の背景**：ダイアログウィンドウの背後に画像を表示します（機能番号：655）。`--screenbackground`
- **情報ボックスの幅** - アイコンとは独立して、情報ボックス内のテキスト領域のサイズを調整します（#665）。
- **aria2 の部分ファイルサポート** — `cacheExtensions` は、項目を「ダウンロード中」としてマークするための設定可能な配列です（デフォルトは `download`、`pkg`、`dmg`。aria2 の場合は `aria2` を追加）。

### 以前に未記録だった引数。

以下の引数は、以前のバージョンでも存在していましたが、ドキュメントには記載されていませんでした。現在、それぞれの引数について、ヘルプテキストが提供されています。`--help <argument>` を参照してください。

| 引数 | 説明 |
|---|---|
| `--helpalignment [left\|centre\|right]` | ヘルプシートのメッセージのテキストの配置を設定します。 |
| `--helpsheetbuttontext <text>` | ヘルプシート上の「閉じる」ボタンのラベルを設定します（デフォルト：`OK`）。 |
| `--iconalttext <text>` | ダイアログアイコンのアクセシビリティラベル。 |
| `--bannerheight <num>` | バナー画像の表示領域の高さをポイント単位で設定します。 |
| `--selectstyle [list\|radio\|searchable\|multiselect]` | 選択リスト全体に適用される、グローバルな表示スタイル。 |
| `--progresstextalignment [left\|right]` | プログレスバーのテキストの水平方向の配置（デフォルト：中央寄せ）。 |
| `--verbose` | 標準エラー出力（stderr）に詳細なログを出力するように設定します。 |
| `--eula` | EULAモード（等幅フォント、スクロール可能）でメッセージを表示します。 |
| `--alwaysreturninput` | すべての終了コードに対して、ユーザーからの入力を返します。終了コードが0の場合だけでなく、他の終了コードの場合にもユーザー入力を返します。 |
| `--hidetimer` | 画像のスライドショーが自動再生中に、カウントダウン表示を非表示にします。 |
| `--listfonts` | 利用可能なすべてのフォント名を標準出力に出力します。 |

### バグ修正。

- **修正点 #632** - 複数選択可能なドロップダウンメニューにおいて、選択されたタグがスクロール可能な表示形式で正しく表示されるようになりました。
- ファイルまたはURLの読み込みにおいて、**存在しないファイルパスが指定された場合のエラーが解消されました**（#654）。
- **ミニ表示**機能は、現在、インラインテキストではなく、構造化されたテキストを表示するように変更されました（#677）。また、**macOS 26 (Tahoe)** 以降のバージョンに合わせて、表示サイズが調整されました（#649）。
- 「プリセット2」の検査：アクティブなインストール状況を自動的に追跡します（#565）。カスタム設定されたステータスと進捗状況のテキストを反映します（#571）。ヘッダーのサブタイトルは、`message` から取得されます（#670）。
- 確認：**`appearance: dark`** は、inspectモードでJSONを設定した場合に有効になります。

### 変更点と非推奨機能について。
- 通知を**`Dialog.app`経由で直接送信する（`--style`なし）ことは非推奨**です。`--style alert` / `--style banner`を使用してください。従来の使用方法はstderrに警告を出力します。
- Removed the stub **`--inspect-schema`** and **`--schema-validate`** commands.
