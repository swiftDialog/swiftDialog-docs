`dialog`コマンドは、`/usr/local/bin/dialog`で利用可能ですが、これはDialogアプリケーションそのものではありません。Dialog.appの実行ファイルを起動する、軽量なコマンドラインインターフェース（CLI）ランチャー（`dialogcli`）です。このコマンドが何をするのかを理解することは、swiftDialogを利用して展開したりスクリプトを作成したりする際に役立ちます。

---

## ランチャーの機能について。

プログラムを実行すると、ランチャーが以下の動作を行います：`dialog`

1. Dialog.appの実行ファイル（バイナリ）を、アプリケーションバンドル内の自身のパスを基準にして特定します。
2. **コマンドファイルを作成します**。これは、`/var/tmp/dialog.log` (または、`--commandfile`で指定されたパス) に存在しない場合に作成されます。もし指定されたパスがシンボリックリンクである場合、セキュリティ上のリスクを避けるため、プログラムの実行を中止します。
3. **現在のGUIユーザーを特定します。**`SCDynamicStoreCopyConsoleUser`を使用します。GUIユーザーがアクティブでなく、`--loginwindow`が指定されていない場合、ランチャーはコード`1`で終了します。
4. **正しいユーザーコンテキストでダイアログを実行します。** ラウンチャは、rootユーザーとして起動される場合（例えば、JamfのポリシーやLaunchDaemonから起動される場合）、`launchctl asuser`を使用して、ログインしているGUIユーザーとしてダイアログを実行します。これにより、ウィンドウが正しいディスプレイセッションに表示されます。
5. **`--pid`を自動で渡します。**ランチャーの自身のPIDが`--pid <pid>`として注入されるため、Dialogは呼び出し元のプロセスを監視し、終了すればダイアログも終了します。
6. **ルート指定された通知** - `--notification` と `--style alert`、または `--style banner` の両方が使用される場合、ランチャーは、メインのダイアログプログラムではなく、適切な組み込み通知ヘルパーアプリに呼び出しを転送します。

## シンボリックリンクの作成。

ランチャーは、`/usr/local/bin/dialog`をそれ自身を指すシンボリックリンクとして作成する`--link`フラグを含みます。rootとして実行する必要があります：

```sh
sudo Dialog.app/Contents/MacOS/dialog --link
```

通常、swiftDialogのインストールパッケージが自動的にこの処理を行います。

## ユーティリティ機能のオプション。

これらのオプションは、Dialogプログラム自体によって処理され、主にシステム管理や導入スクリプトで使用されます。

### `--setappicon <file>`

指定された画像ファイルを swiftDialog アプリケーションのアイコンに設定し、その後すぐに終了します。また、組み込まれた通知ヘルパーアプリのアイコンも更新されます。

```sh
dialog --setappicon /path/to/custom-icon.png
```

これは一時的な操作であり、Dialogはウィンドウを表示しません。この機能は、インストール後に、Dockアイコンや通知を貴社のブランドイメージに合わせてカスタマイズするために用意されています。

### `--callingpid <int>`

指定されたプロセスIDを監視します。もしそのプロセスが終了した場合、Dialogは自動的にコード`40`で終了します。

```sh
dialog --title "Installing..." --callingpid 12345
```

この情報は、`dialogcli` ランチャーによって自動的に注入されます（ランチャー自身のプロセスIDを使用）。そのため、Dialogを実行しているスクリプトやプロセスが終了すると、Dialogも終了します。別のプロセスIDを明示的に指定することも可能ですが、その場合、Dialogはそのプロセスに紐付けられます。しかし、そのような使用方法はサポートされていません。

**終了コード40** は、監視対象のプロセスが終了したためにDialogが終了した場合に返されます。
